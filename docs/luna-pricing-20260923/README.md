输入超过边界后对该请求使用长档，不是仅对超出部分加价。`group_ratio_override` 保持数字 1，用于豁免普通/用户专属分组倍率；独立的拼车模型倍数仍会作用于命中的拼车请求。不能同时恢复历史 ×2 表达式又保留拼车 ×2，否则会重复加价。分组豁免不修改路由、权限、套餐及钱包充值折算。

实际扣费路径：动态表达式基价 → 模型专属组倍率覆盖1 → 命中时应用拼车独立倍数 → 按原算法取整结算。请求/任务采用计价时冻结的有效倍率，不能根据完成时的最新策略重算旧请求。未配置覆盖的模型仍走原分组/用户专属倍率。下面前三个选项均是完整JSON映射，维护时读取现值后合并指定模型条目，不能用只包含Luna的对象覆盖全表。

| 配置键 | 当前Luna值 | 用途 |
|---|---|---|
| `billing_setting.billing_mode` | `tiered_expr` | 启用动态计费 |
| `billing_setting.billing_expr` | 迁移时官方预设长短档基价，已去除表达式内 ×2 | 决定输入、输出、缓存读写基价 |
| `billing_setting.group_ratio_override` | 数字 `1` | 替代普通、VIP和自动选中组的最终倍率，不改变分组路由 |
| `CarpoolBillingPolicy` | 4 个纳管组内，8 个 Luna 完整名称分别 ×2 | 拼车后台管理；精确匹配组与模型，独立于普通组折扣 |

- 恢复参与普通分组计费：移除目标Luna名称的 `group_ratio_override` 条目，不要写0（0表示免费倍率）；无需重新编译。拼车独立策略仍可能继续叠加，需要按目标售价一并评估，不能将删除覆盖误认为清除了拼车倍数。
- 恢复所有组均用基价：当前表达式已经是迁移时预设基价；保留覆盖1，并通过拼车模型倍数入口撤销目标加价、读回确认。不要只改 `ModelRatio`，也不要直接清库中的策略，拼车同步可能重新下发。
- 配置接口更新可即时触发重载；直接改库通常需等待现网同步周期（约60秒）并用API/消费日志验收，不应仅看数据库认定已生效。
- 新增Luna别名：显式更新上述三个定价映射，按需加入拼车模型倍数规则。计费按完整模型名匹配，不自动识别未来型号或所有包含luna的字符串。

## 同步价格与升级检查

**拼车自动同步不会动 Luna**：拼车后台的「模型价格」每天同步两次，并提供「还原备份」。代码里写死了：名称含 `luna`（不区分大小写）的模型一律锁定（拼车 `service/modelprice/service.go` 的 `isLocked`），同步时不比较、不写入，还原备份时也会跳过；如果一次写入会改到锁定模型，整次写入直接拒绝（`write.go` 的 `lockedUnchanged`）。另外，拼车每 3 天的价格复核（R5）会比对 Luna 表达式和分组倍率覆盖，一旦被改就发邮件告警。

**会覆盖 Luna 的是 new-api 后台自己的同步与导入**，操作时注意：
1. 在 new-api 后台「同步上游倍率 / 价格」之前，先备份三份映射，并**取消勾选全部 8 个 Luna 名称**，其他模型照常同步。
2. 同步动态表达式可能改变 Luna 的基价与档位；迁移后原本就使用预设基价，不再依赖表达式内加价。new-api 自身没有防覆盖锁；拼车独立加价由 `CarpoolBillingPolicy` 控制。同步后对照备份、预期新基价及 `/api/pricing`，并检查独立倍数；不要用 10-18 的旧 ×2 表达式作当前恢复值。
3. 分组豁免是独立配置键，但完整配置导入/恢复可能覆盖它；同步工具行为未逐一验证，执行后必须检查实际值。
4. 升级到上游原版前合并本次后端字段/倍率处理及前端展示补丁；缺少后端补丁会重新叠加分组倍率，缺少前端补丁会显示错误折扣价。
5. 验收 `/api/pricing`：Luna记录须有 `group_ratio_override:1` 和正确基价表达式；非Luna不应新增覆盖。价格页的基价不等于已加入拼车独立倍数的实扣。消费日志分别核对 `other.group_ratio=1`、命中时的 `carpool_ratio=2` 及计价时点，用既有核价算法复算。
