## 后续配置维护

实际扣费路径：动态表达式（包含1.3倍售价）→模型专属组倍率覆盖1→最终quota。未配置覆盖的模型仍走原分组/用户专属倍率。三个选项均是完整JSON映射，维护时读取现值后合并指定模型条目，不能用只包含Luna的对象覆盖全表。

| 配置键 | 当前Luna值 | 用途 |
|---|---|---|
| `billing_setting.billing_mode` | `tiered_expr` | 启用动态计费 |
| `billing_setting.billing_expr` | 官方Standard长短档×1.3 | 决定输入、输出、缓存读写单价 |
| `billing_setting.group_ratio_override` | 数字 `1` | 替代普通、VIP和自动选中组的最终倍率，不改变分组路由 |

- 恢复参与分组计费：只移除目标Luna名称的 `group_ratio_override` 条目，不要写0（0表示免费倍率）；无需重新编译。恢复后仍按表达式当前价格再乘组倍率。
- 恢复官方原价：将表达式中各档单价改为官方值；若仍需不参与分组折扣，保留覆盖1。不要仅修改 `ModelRatio`，它不参与已启用的动态计费。
- 配置接口更新可即时触发重载；直接改库通常需等待现网同步周期（约60秒）并用API/消费日志验收，不应仅看数据库认定已生效。
- 新增Luna别名：显式更新上述三个映射。功能按完整模型名匹配，不自动识别未来型号或所有包含luna的字符串。

## 同步价格与升级检查

1. 同步前备份三份映射，默认取消勾选Luna；其他模型正常同步。
2. 同步动态表达式可能把Luna×1.3售价覆盖成官方原价；只同步普通模型倍率不一定改变动态价格。当前没有防覆盖锁或自动乘1.3功能。
3. 分组豁免是独立配置键，但完整配置导入/恢复可能覆盖它；同步工具行为未逐一验证，执行后必须检查实际值。
4. 升级到上游原版前合并本次后端字段/倍率处理及前端展示补丁；缺少后端补丁会重新叠加分组倍率，缺少前端补丁会显示错误折扣价。
5. 验收 `/api/pricing`：Luna记录须有 `group_ratio_override:1` 和正确表达式；非Luna不应新增覆盖。切换0.2/0.32/1分组报价应一致，并核对实际消费日志 `other.group_ratio=1`。
